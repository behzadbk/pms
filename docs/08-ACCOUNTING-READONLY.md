# اتصال فقط‌خواندنی به نرم‌افزار حسابداری + پروفایل مالی

«همین» نرم‌افزار حسابداری نیست. دفتر کل، حقوق‌ودستمزد و اسناد در نرم‌افزار حسابداری خودِ مجموعه می‌مانند؛ ما فقط می‌خوانیم و در رابط خودمان نشان می‌دهیم. از این بخش هیچ داده‌ای به حسابداری نوشته نمی‌شود و چیزی هم در دیتابیس ما کپی نمی‌شود.

## پنل حسابداری ← «پروفایل مالی» (`/accountant/profiles`)
- تب **واحدها**: مانده، دوره‌های معوق، آخرین پرداخت. با کلیک روی هر واحد: شارژ ثابت، **شارژ متغیر** (مازاد خدمات/مشاعات و کافه/رستوران)، جریمه‌ی دیرکرد، پرداخت‌ها، جدول دوره‌ها و گردش حساب.
- تب **کارمندان**: فیش حقوقی، پرداخت‌ها، پاداش و جریمه.
- فقط `accountant` و `admin` به API دسترسی دارند؛ ساکنین، کارکنان و نگهبانی هرگز (وضعیت تسویه‌ی هر واحد برای دیگران پنهان است).

## معماری (`backend/finance-service/src/ledger/`)
| فایل | نقش |
|---|---|
| `provider.ts` | شکل یکدست داده + دو interface: `UnitLedgerSource`، `StaffLedgerSource` |
| `internal-unit.source.ts` | منبع پیش‌فرض واحدها: همان دفتر شارژ/پرداخت دیتابیس ساختمان (صدور با فرمول یا ورود از فایل). فقط SELECT |
| `staff.sources.ts` | `NoStaffSource` (پیش‌فرض: «اتصال برقرار نیست»، هیچ داده‌ای نمی‌سازد) و `DemoStaffSource` (فقط پیش‌نمایش) |
| `ledger.controller.ts` | `GET /accounting/status · /units · /units/:id/profile · /staff · /staff/:id/profile` |

انتخاب منبع حقوق: `ACCOUNTING_STAFF_SOURCE=none` (پیش‌فرض) یا `demo`. حالت `demo` در `NODE_ENV=production` هرگز فعال نمی‌شود (قانون محصول: ساختمان تازه خام و خالی است).

## وصل کردن نرم‌افزار حسابداری واقعی
1. یک کلاس جدید بنویسید که `UnitLedgerSource` و/یا `StaffLedgerSource` را پیاده کند (مثلاً `HesabfaSource`) و داده‌ی آن نرم‌افزار را به شکل `UnitProfile` / `StaffProfile` ترجمه کند.
2. در `ledger.module.ts` به‌جای `InternalUnitSource` / `pickStaffSource` ثبتش کنید.
3. کنترلر و فرانت دست نمی‌خورند. کلید/آدرس API را فقط در env بگذارید (نه در ریپو).

## تأیید
- `nest build` بدون خطا، jest (`ledger.spec.ts`) سبز.
- روی PostgreSQL 16 واقعی با ۱۰۰ واحد × ۳ ماه شارژ: جمع مانده ۱۳۴٬۷۵۲٬۰۰۰ و ۴۱ واحد بدهکار، دقیقاً برابر فایل شبیه‌سازی.
- `tsc -b` بدون خطا؛ صفحه‌ها در مرورگر واقعی (با API شبیه‌سازی‌شده روی همان داده) دیده شد و خطای کنسول نداشت.
