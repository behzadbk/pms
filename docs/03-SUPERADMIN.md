# پنل سوپر ادمین — ورود، ساختمان‌ها و سطح‌بندی سرویس

این سند بخش سوپرادمین (سطح پلتفرم) را توضیح می‌دهد: صفحه‌ی ورود جدا، لیست
ساختمان‌های تحت همکاری با وضعیت مالی اشتراک، و تعریف برج/ساختمان جدید با
انتخاب سطح سرویس.

## ۱) سطوح سرویس

سه سطح تعریف شده که تعیین می‌کنند کدام ماژول‌ها برای یک مجتمع فعال باشد.
منبع حقیقت در دو فایل هم‌نسخه است:

- `backend/identity-service/src/platform/tiers.ts`
- `frontend/src/lib/tiers.ts`

| سطح | برای چه ساختمان‌هایی | ماژول‌ها |
| --- | --- | --- |
| **ساده** | ساختمان‌هایی که هیچ مشاعاتی ندارند و فقط به نظم مالی نیاز دارند | شفافیت مالی و صندوق، ثبت و صدور شارژ، پرداخت آنلاین شارژ، ثبت گزارش خرابی (تیکت)، ثبت خریدها و هزینه‌ها، سرویس‌های دوره‌ای، برنامه نظافت، اطلاعیه‌ها (۸ ماژول) |
| **اقتصادی** | چند مشاعات دارند (سینما، باشگاه) اما لابی، نگهبانی و تأسیسات ندارند | همه‌ی موارد ساده + رزرو مشاعات، قوانین رزرو هوشمند، تقویم بصری زنده، رأی‌گیری (۱۲ ماژول) |
| **حرفه‌ای** | برج‌های کامل با لابی، نگهبانی و تأسیسات | همه‌ی موارد اقتصادی + پنل نگهبانی/لابی، کد مهمان (QR)، مرسولات پستی، تردد خودرو و پارکینگ، سفارش غذا و کافی‌شاپ، مدیریت تأسیسات (CMMS)، داشبورد لاگ (۱۹ ماژول) |

قیمت پایه‌ی هر سطح به ازای هر واحد در ماه: ساده ۲۵٬۰۰۰ / اقتصادی ۴۰٬۰۰۰ /
حرفه‌ای ۶۵٬۰۰۰ تومان. مبلغ اشتراک پیشنهادی هنگام تعریف ساختمان =
قیمت پایه × تعداد واحد (قابل override دستی در همان فرم).

## ۲) کاربران سوپرادمین

سوپرادمین‌ها در جدول جدید `identity.platform_admins` نگهداری می‌شوند — نه در
`identity.users`. دلیل: این کاربر به هیچ tenant‌ای تعلق ندارد، پس نه
`tenant_id` دارد و نه باید تحت RLS مربوط به یک مجتمع قرار بگیرد. توکن صادرشده
برای او `tenant_id: null` و `role: 'super_admin'` دارد.

دو کاربر اولیه‌ی محیط dev (رمز هر دو `1234`): `behzad` و `amir`.

> این رمز فقط برای توسعه است؛ پیش از استقرار حتماً عوض شود.

## ۳) اجرا

```bash
cd backend/identity-service
psql "$DATABASE_URL" -f prisma/migrations/001_enable_rls.sql          # اگر قبلاً اجرا نشده
psql "$DATABASE_URL" -f prisma/migrations/002_platform_admins_and_tiers.sql
psql "$DATABASE_URL" -f prisma/seed-dev.sql                            # tenant و کاربران نمونه
psql "$DATABASE_URL" -f prisma/seed-platform-admins.sql                # behzad / amir + ۳ ساختمان نمونه
npm run start:dev                                                      # پورت ۳۰۰۱

cd ../../frontend
npm run dev                                                            # پورت ۵۱۷۳
```

سپس در مرورگر: `http://localhost:5173/super-admin/login`

## ۴) Endpointها (identity-service)

| متد | مسیر | دسترسی | توضیح |
| --- | --- | --- | --- |
| POST | `/auth/platform-login` | عمومی | ورود سوپرادمین با `{username, password}` |
| GET | `/auth/me` | توکن معتبر | هم کاربر عادی و هم سوپرادمین را برمی‌گرداند |
| GET | `/platform/tiers` | `super_admin` | ماتریس سطوح |
| GET | `/platform/buildings` | `super_admin` | لیست ساختمان‌ها + خلاصه (MRR، مانده بدهی، تفکیک سطوح) |
| GET | `/platform/buildings/:id` | `super_admin` | جزئیات یک ساختمان |
| POST | `/platform/buildings` | `super_admin` | تعریف ساختمان/برج جدید |
| PATCH | `/platform/buildings/:id` | `super_admin` | ویرایش (سطح، وضعیت، اطلاعات مالی) |
| PATCH | `/platform/buildings/:id/settle` | `super_admin` | ثبت تسویه‌ی اشتراک |

مسیرهای `/platform/*` علاوه بر JwtAuthGuard با `@Roles('super_admin')` محافظت
می‌شوند؛ توکن یک مدیر ساختمان عادی روی آن‌ها ۴۰۳ می‌گیرد (تست شد).

## ۵) وضعیت مالی در لیست ساختمان‌ها

منظور از «وضعیت مالی» تسویه‌ی اشتراک نرم‌افزار با ما است (نه وصول شارژ داخلی
ساکنین). ستون‌های مربوطه روی `identity.tenants`:

- `monthly_fee` — مبلغ اشتراک ماهانه
- `outstanding_amount` — مانده‌ی بدهی
- `billing_status` — `settled` (تسویه‌شده) | `due` (سررسید نزدیک) | `overdue` (معوق)
- `last_payment_at` / `next_due_at`

## ۶) مسیرهای فرانت‌اند

| مسیر | صفحه |
| --- | --- |
| `/super-admin/login` | ورود سوپرادمین (جدا از `/login` ساکنین) |
| `/super-admin/buildings` | لیست ساختمان‌ها + فرم تعریف برج جدید |
| `/super-admin/plans` | سطوح سرویس و جدول مقایسه‌ی قابلیت‌ها |
| `/super-admin` | داشبورد پلتفرم (هنوز mock) |

گارد `RequireSuperAdmin` در `App.tsx` علاوه بر لاگین، نقش کاربر را هم چک
می‌کند و کاربر لاگین‌نشده را روی مسیرهای `/super-admin/*` به
`/super-admin/login` می‌فرستد، نه `/login`.

## ۷) راستی‌آزمایی انجام‌شده

- فرانت‌اند: `npm install` + `tsc -b --force` (صفر خطا) + `vite build` کامل
  با تولید service worker (۴۴ ورودی precache) + `oxlint`.
- بک‌اند: `npm install` + `nest build` (صفر خطا).
- end-to-end روی یک PostgreSQL 16 واقعی: اجرای migration و seed، ورود
  `behzad/1234` و `amir/1234`، رد شدن رمز اشتباه (۴۰۱)، `GET /auth/me`،
  لیست ساختمان‌ها و خلاصه، ساخت ساختمان جدید با محاسبه‌ی خودکار اشتراک
  (اقتصادی × ۳۰ واحد = ۱٬۲۰۰٬۰۰۰)، رد subdomain تکراری (۴۰۹)، رد سطح
  نامعتبر (۴۰۰)، ۴۰۳ برای توکن مدیر ساختمان، ۴۰۱ بدون توکن، و ثبت تسویه.

## ۸) انجام‌نشده / برای بعد

- داشبورد پلتفرم (`/super-admin`) و صفحه‌ی تراکنش‌ها هنوز از `mockData.ts`
  می‌خوانند؛ فقط صفحه‌ی ساختمان‌ها به API واقعی وصل است.
- اعمال feature flagهای سطح سرویس روی خود پنل مجتمع‌ها (یعنی مخفی کردن
  منوی نگهبانی برای یک ساختمان «ساده») هنوز پیاده نشده — ماتریس آماده است،
  فقط باید هنگام لاگین کاربر، `tier` مجتمع در توکن/`/auth/me` برگردانده و در
  `nav.ts` فیلتر شود.
- مدیریت کاربران سوپرادمین از داخل پنل (افزودن/حذف) — فعلاً فقط از طریق SQL.
