## باگ‌های پیدا و رفع‌شده

### امنیتی (بحرانی)
1. **refreshToken به‌جای accessToken پذیرفته می‌شد** — توکن ۳۰ روزه روی همه‌ی endpointها کار می‌کرد و accessToken هم می‌توانست نشست را تمدید کند. → فیلد `typ` در توکن + رد در `JwtStrategy`، gatewayهای WebSocket و `/auth/refresh`.
2. **Webhook پرداخت بدون امضا** — هر کسی با یک `paymentId` می‌توانست شارژ را «پرداخت‌شده» کند. → امضای HMAC اجباری (`PAYMENT_WEBHOOK_SECRET`)، idempotent، مسیر جدید `POST /payments/webhook/:gateway/:tenantId`.
3. **کلید پیش‌فرض `dev-only-secret`** — اگر `JWT_SECRET` در production ست نمی‌شد، هر کسی می‌توانست توکن `super_admin` جعل کند. → در `NODE_ENV=production` سرویس بدون کلید اصلاً بالا نمی‌آید.
4. **نگهبانی بدون کنترل نقش** — ساکن می‌توانست ورود مهمان ثبت کند، کد مهمان استعلام کند، مرسوله ثبت/تحویل کند و برای واحد دیگران کد مهمان بسازد. → `@Roles` + بررسی مالکیت واحد.
5. **ساکن می‌توانست سفارش غذای دیگران را لغو کند** و **تعداد منفی** در سبد، مبلغ سفارش را منفی (‎-2,100,000) می‌کرد.
6. فرانت: **سوییچر نقش در نسخه‌ی واقعی فعال بود** و ساکن با تایپ `/admin/...` پنل مدیریت را می‌دید. → سوییچر فقط در dev (یا `VITE_DEMO_ROLE_SWITCHER=true`) + گارد نقش روی همه‌ی مسیرها.
7. کش API در service worker بعد از خروج پاک نمی‌شد (مشکل دستگاه مشترک).

### عملکردی (کار نمی‌کرد)
8. **PWA نصب‌شده همیشه صفحه‌ی «آفلاین هستید» نشان می‌داد** — `navigateFallback: '/offline.html'` برای *همه‌ی* ناوبری‌ها سرو می‌شد؛ هر رفرش یا باز کردن اپ = صفحه‌ی آفلاین. → `index.html`.
9. **ثبت مرسوله همیشه 500** — ستون `photo_url` در جدول نبود. → مایگریشن `guard/002_parcels_photo_url.sql`.
10. **صدور شارژ ماهانه همیشه 500** — `inconsistent types deduced for parameter $3`.
11. **Webhook پرداخت هیچ‌وقت پرداخت را پیدا نمی‌کرد (همیشه 404)** — `withPlatformAccess` روی نقش `app_user` با RLS اجباری.
12. **ساختمان جدیدِ سوپرادمین هیچ کاربری نداشت** — مشتری راهی برای ورود نداشت. → فیلد ایمیل/رمز مدیر اولیه در فرم و API (در یک تراکنش).
13. **کپی `.env.example` سرویس را کرش می‌داد** (`JWT_PUBLIC_KEY=` خالی) و با فایل `.env`، امضا و اعتبارسنجی توکن با دو کلید متفاوت انجام می‌شد (همه 401). → `registerAsync` + `jwtSecret()`.
14. ورود بعد از لاگین: ساکن/نگهبان/کارمند به `/admin` هدایت می‌شدند؛ رفرش صفحه همیشه به داشبورد پرت می‌کرد؛ سوپرادمین روی `/admin` صفحه‌ی خالی می‌دید.
15. شناسه یا تاریخ نامعتبر در URL → 500. → فیلتر سراسری خطای PostgreSQL (400/409).
16. کد مهمانِ منقضی/مصرف‌شده هنگام check-in دوباره بررسی نمی‌شد؛ تحویل دوباره‌ی مرسوله و پرداخت دوباره‌ی شارژ پرداخت‌شده ممکن بود.
17. regex فیلد subdomain در مرورگر خطا می‌داد (`Invalid character class`).

## اجرای دوباره‌ی تست‌ها

```bash
cd db && DATABASE_URL=postgres://postgres:postgres@localhost:5432/pms ./migrate.sh --reset
bash tests/run-all-services.sh           # بعد از nest build همه‌ی سرویس‌ها
python3 tests/e2e_api.py                 # ۵۷ سناریو
cd frontend && npm run build && npx vite preview --port 4173 &
node tests/ui_human_test.mjs             # نیازمند: npm i playwright
```

> تست e2e روی دیتابیس تازه (`--reset`) طراحی شده؛ اجرای دوباره روی همان دیتابیس چند سناریو را (به‌درستی) 409 می‌کند.
